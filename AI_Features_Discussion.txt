  ---
  Feature ideas, ranked by build effort vs value

  Tier 1 — Cheap, fast to build, high perceived value (start here)

  1. SMS / notification drafting assistant
  You already have the SMS Center + sms_logs. Add an "AI draft" button: staff picks intent (absence, fee due, holiday, event) → Haiku drafts the
  message in the school's tone/language → staff edits → sends.
  - Cost: tiny (one short completion).
  - Regulatory note: DLT templates are fixed by law — so AI fills approved template variables, it doesn't write free-form SMS. Frame it as "draft
  the variable content."

  2. Report-card remarks generator
  Teacher enters marks → overnight Batch API job drafts a personalized 1–2 line remark per student from their marks trend ("improved in Maths,
  needs focus in English"). Parents love this; teachers save hours.
  - Cost: batch = 50% off, runs once per exam cycle. Negligible per student.

  3. Homework / announcement expander
  Teacher types "fractions worksheet, submit Friday" → AI expands into a proper homework description. Reuses your existing homework/announcements
  modules.

  Tier 2 — Agentic (the real differentiator, moderate build)

  4. Parent chatbot in the mobile app ⭐ highest impact
  A chat tab where parents ask in plain language: "how much fee is pending?", "what's my child's attendance this month?", "when's the next exam?".
  This is a tool-use agent where the tools are your existing mobile read endpoints (/mobile/fees/outstanding, /mobile/student/attendance,
  /mobile/student/marks, homework, announcements). The model just decides which to call and phrases the answer.
  - Why low cost to build: the tools already exist and are already tenant-scoped + child-scoped. You're wrapping them, not building new data
  access.
  - Why low cost to run: Haiku + cache the child context per session + rate-limit per parent.
  - Deflects support load off the school office — a concrete selling point.

  5. Admin natural-language reports
  Staff types "students in class 6 with over ₹5,000 outstanding" or "attendance trend for class 8 last 3 months" → agent calls your existing report  endpoints / runs scoped read queries → returns a table + summary. You already have ~20 report endpoints; this is a natural-language front door
  to them.

  Tier 3 — Analytics (mostly SQL + thin AI layer = very cheap)

  6. At-risk student early warning
  Nightly batch combines signals you already store: attendance drop + marks decline + fee defaults → flags students needing intervention, with a
  one-line AI explanation. 90% of this is SQL; AI only writes the human summary. Genuinely valuable to principals.

  7. Fee-collection insights
  "Which classes/routes have the worst collection %, and what's the likely pattern?" — aggregate in SQL, AI narrates.

  Tier 4 — Content generation (on-demand, chargeable, higher tokens)

  8. Practice question / worksheet generator — teacher picks subject + class + topic → AI generates questions. Higher token use, so meter it or
  make it a Premium-only quota.

  ---
  How to deliver it (fits your stack)

  - Backend: a new AiController + AiService in your .NET 4.8 API that calls Anthropic via HttpClient. Same pattern as your existing repos/helpers.
  - Agent tools = existing repository methods. You don't expose the DB to the model; you expose a handful of read functions (GetStudentFeeSummary,
  GetAttendance, etc.) as tool definitions. Every call runs inside TenantContext — no cross-tenant leakage, which is critical for the "schools are
  legally sensitive about student data" constraint in your own project guide.
  - New module: AI_ASSISTANT in the modules table, plan_tier = Premium. Gate every AI endpoint with [RequireModule(ModuleCodes.AiAssistant)] — you
  already have this filter.
  - Usage table: ai_usage_logs (tenant, feature, tokens, cost) for billing + budget enforcement, mirroring your sms_logs pattern.

  ---
  Recommended starting point

  Build #1 (SMS draft) first — smallest surface, proves the plumbing (Anthropic call, tenant scoping, usage logging) in days. Then #4 (parent
  chatbot) — it's the feature schools will actually pay Premium for, and the tools already exist.

  ---
  Risks to decide on up front

  - Data privacy: student data goes to the Anthropic API. Anthropic doesn't train on API data, but schools are sensitive — make AI opt-in per
  school group, and minimize PII (send IDs/aggregates where the task allows). Worth a line in your subscription terms.
  - Numbers must be grounded: never let the model state a fee balance from memory — force it through a tool call. Non-negotiable for trust.
  - Language: Indian regional languages — Claude handles these well; let schools set a preferred language in school_settings.
