Good time to step back and plan this properly. Let me think through this as both architect and PM.

  ---
  Key Principle: Foundation Before Features

  Every screen in the school app needs tenant resolution, auth, and permission checks working first. Building a module screen before  
  those are solid means rebuilding it later.

  ---
  Two Apps — Two Tracks

  Track A: Control App (simpler, validates multi-tenant arch early)
  Track B: School App (main product)

  Run Track A first — it's smaller, and getting the multi-tenant DB routing working there de-risks Track B completely.

  ---
  Phases

  Phase 0 — Project Setup (do once, get right)

  API (.NET 4.8 Web API):
  - Solution with 3 projects:
  AscentSchools.sln
  ├── AscentSchools.API        ← single Web API, serves both apps
  ├── AscentSchools.Core       ← models, interfaces, constants
  └── AscentSchools.Data       ← repositories, DB context, migrations
  - Multi-tenant DB connection factory (resolve tenant DB from subdomain/JWT claim)
  - Response envelope standard: { success, data, message, errors }
  - Global exception handler
  - JWT token setup

  React (two separate apps):
  ascent-control-app/    ← Ascent internal admin portal
  ascent-school-app/     ← School-facing app (tenant)

  - Folder structure, routing, axios base setup, env config
  - Shared component library (buttons, tables, forms, modals) — used by both apps

  ├──────────────────────────────────┼─────────────────────────────────┤

  Step 2c — API Middleware (non-UI but critical)
  - TenantMiddleware — reads subdomain → resolves group_id → sets tenant DB connection
  - ModuleAccessMiddleware — checks group_modules + school_modules before controller runs
  - Permission attribute on every controller action: [RequirePermission("STUDENT_FEE.COLLECT")]

  Deliverable: Full login + RBAC working. A Fee Clerk can log in and gets 403 on anything outside their permissions.

  ---
  Decisions to Make Before Writing Code

  1. ORM or raw ADO.NET? — Dapper is a good middle ground for .NET 4.8 (lightweight, SQL-friendly, easy multi-tenant connection       
  switching). Entity Framework works too but multi-tenant DB switching is more complex.
  2. React state management? — Redux Toolkit or Zustand? For this scale Zustand is simpler.
  3. UI component library? — Ant Design or MUI? Both have tables, forms, date pickers needed for school app.
  4. Tenant DB provisioning — When a school group is onboarded from the control app, does the API auto-create the tenant DB and run   
  tenant_tables.sql, or is it a manual DBA step?
  5. JWT expiry + refresh token strategy?
